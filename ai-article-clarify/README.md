# AI Article Clarify

从**内容、表达、阅读**三个层面编辑已有中文文章，处理空话、重复、翻译腔与机械结构，保住事实、作者原意和指定格式。

适合博客、观点文章、技术解释、产品介绍，以及具有明确文体要求的其他中文稿件。接收人工或 AI 初稿；不绑定公众号、固定作者、配色、尾图或上传流程。

## 三层机制

| 层面 | 重点 | 做法 |
| --- | --- | --- |
| 内容 | 文章要讲什么 | 围绕本篇目的裁定支线、详略和顺序，用材料讲透核心；保留指定结构。 |
| 表达 | 中文怎样说清楚 | 整理动作、语序、指代、关联词、语气与文化背景，保住条件和事实。 |
| 阅读 | 整篇能否顺着读 | 检查衔接、停顿、标题承诺、图文位置与实际载体；无预览不虚报验收。 |

三层是编辑视角，**不是要求所有文章写成三个章节**。好句子可以保留，专业术语、必要限定和有作用的重复也可以保留；不靠禁词表、故意错字或批量加口头禅制造自然感。

## 安装

本目录是完整 Skill 包。将整个 `ai-article-clarify` 文件夹复制到你的 Skill 目录；使用本仓库的 Codex 本地约定时，可放入 `~/.codex/skills/`，配置过其他目录则使用对应位置。保留 `references/` 与入口的相对关系，不只复制 SKILL.md。

可以下载仓库 ZIP 后复制该目录，或克隆仓库：

```sh
git clone https://github.com/Willis1214/willis-ai.git
```

已有同名安装时先比较并保留自己的改动，再决定更新。安装完成后由宿主发现/重新加载 Skill；不同宿主的发现机制可能不同。其他支持 Skill 的工具可按其目录规则安装，未声明逐一验证兼容性。

## 使用

提供原稿、原始要求和必要材料即可；读者、文体、必须保留项与修改范围有明确要求时一并说明。无需填写固定表单。

**整篇终修**

```text
用 $ai-article-clarify 修改下面的技术博客。
面向刚接触这个话题的读者，保留机制解释、两个例子和所有事实条件。
直接给完整修订稿，影响原意的问题单独说明。
[原稿与材料]
```

**保留强结构**

```text
用 $ai-article-clarify 修这篇报告。
必须保留“层面—重点—做法—细节”的结构，只处理重复、含混和不自然的中文。
[原稿]
```

**只审阅 / 局部修改**

```text
用 $ai-article-clarify 只审阅这篇文章，不重写。指出有依据的问题、影响和改法。
```

```text
用 $ai-article-clarify 只改标题。正文保持原样，标题承诺必须由正文支持。
```

## 输入和交付

- 输入：已有中文稿、写作要求与可用材料；按需带标题摘要、图片、读者、文体及格式约定。
- 输出：授权范围内的完整修订稿、标题摘要或审阅意见，必要时说明重要含义变动和图文要求。
- 流程：读懂本篇 → 内容取舍 → 中文表达 → 阅读检查 → 事实与范围复核。
- 边界：不从零选题写作、不承担独立英文稿编辑、不鉴定 AI 来源、不自动出图/上传/发布。稿件事实未经独立查证时不宣称核验完成。

查看 [改稿示例](examples/before-after.md) 和 [行为案例](evals/README.md)。示例是说明性材料，不是实测效果数据。

## 效果与限制

检查主线是否更清楚、中文是否更自然、事实条件是否完整、阅读是否连贯。修改数量、删字比例和检测器分数都不是验收依据。输出质量取决于原稿材料、任务说明与实际执行模型；本包没有跨模型、全体文体的系统对照数据。
